# 踩坑清单：现象 → 原因 → 解法

> 按严重度排序。每条都来自真实排障过程。

---

## 🔴 致命级（装不上 / 页面打不开）

### 1. Zabbix 6.0 在 CentOS 7 上根本没有 server 包

- **现象**：按 6.0 官方源安装 `zabbix-server-mysql` 报找不到包。
- **原因**：Zabbix 官方从 **5.2 起不再为 RHEL/CentOS 7 打包**，6.0 支持列表里没有 CentOS 7。
- **解法**：CentOS 7 一律用 **5.0 LTS**；要 6.0 只能源码编译。
- **教训**：选版本前先看官方 el7 仓库里到底有什么包，别照教材抄。

### 2. 版本错配：server 5.0 + web 6.0 混装

- **现象**：接手一台「装到一半」的机器，`rpm -qa` 显示 `zabbix-server-mysql-5.0.47` 和 `zabbix6.0-web-6.0.29` 同时存在。
- **原因**：前后两次安装用了不同的 Zabbix 大版本源。
- **解法**：前端和 server **必须同大版本**。卸载 6.0 web（`zabbix6.0-web` / `zabbix6.0-web-mysql` / `zabbix6.0` / `zabbix6.0-selinux`），统一到 5.0。

### 3. 5.0 官方 el7 仓库也没有 Web 前端包

- **现象**：server 装好了，但 `zabbix-web-mysql` 等包找不到。
- **核实**：5.0 的 el7 仓库只有 agent/agent2/server/proxy 等，**没有 `zabbix-web-*`**。
- **解法**：前端从源码包取 `https://cdn.zabbix.com/zabbix/sources/oldstable/5.0/zabbix-5.0.47.tar.gz`。

### 4. 5.0 源码包前端目录叫 `ui/`，不是 `frontends/php`

- **现象**：照老教程 `cp -a zabbix-5.0.47/frontends/php/. /usr/share/zabbix/` 报「目录不存在」。
- **原因**：5.0 改版，前端目录改名 `ui/`。
- **解法**：`cp -a zabbix-5.0.47/ui/. /usr/share/zabbix/`。

### 5. 源码版前端配置文件路径不是 `/etc/zabbix/web/`（最隐蔽）

- **现象**：Web 能打开、PHP 正常，但一直跳安装向导 setup.php。
- **原因**：RPM 版读 `/etc/zabbix/web/zabbix.conf.php`；**源码版读 `<前端根>/conf/zabbix.conf.php`**。
- **解法**：配置放 `/etc/zabbix/web/`，再软链到 `/usr/share/zabbix/conf/`。

## 🟠 必踩级（环境本身的问题）

### 6. CentOS 7 已 EOL，官方 yum 源全废

- **现象**：`yum makecache` 请求 `mirrorlist.centos.org` 全失败。
- **解法**：换阿里云 vault 归档源 `centos-vault/7.9.2009/`。

### 7. 老 ca-certificates 导致 https 报「证书已过期」

- **现象**：访问 `repo.zabbix.com` 报 `SSL certificate problem: certificate has expired`。
- **原因**：DST Root CA X3 过期。
- **解法**：换源后先 `yum -y update ca-certificates`。

### 8. 版本上下限卡得死（猜不得）

| 组件 | Zabbix 5.0 要求 | CentOS 7 自带 | 实际采用 |
|---|---|---|---|
| 数据库 | MariaDB 10.0~10.6 | 5.5 ❌ | 10.6.28 ✅ |
| PHP | ≥7.2 | 5.4 ❌ | rh-php73=7.3.33 ✅ |

### 9. MariaDB 5.5 → 10.6 原地升级

- **现象**：直接 `yum install MariaDB-server`（10.6）后，能否读取旧的 5.5 数据目录？
- **实测**：**能**。旧 `/var/lib/mysql` 被 10.6 直接读取，166 张表 + zabbix 用户全保留，`mysql_upgrade` 全 OK。
- **注意**：卸载 `mariadb-libs` 会**连带删除 `zabbix-server-mysql`**（依赖关系），升级后需重装。

### 10. agent 主机名 / 接口 IP 必须与库完全一致

- **现象**：`zabbix_server.log` 刷 `host [zabbix] not found`。
- **原因**：库默认主机名 `Zabbix server`、接口 `127.0.0.1`，只改 agent 配置不同步库。
- **解法**：库内 `UPDATE hosts` / `UPDATE interface` 一起改。

### 11. 模板机时间跑偏（快 8 小时）

- **现象**：系统时间比真实快 8 小时，出图全乱。
- **原因**：`tools.syncTime=FALSE`，RTC 被当 UTC。
- **解法**：装 chrony 并开机自启。

## 💡 自动化技巧（可复用）

不必在虚拟机控制台手动敲命令，通过 VMware Tools 通道（vmrun）执行脚本：

```bash
VMRUN="/d/app/vmware/vmrun.exe"
vmrun -T ws checkToolsState "<vmx路径>"
vmrun -T ws -gu root -gp <密码> copyFileFromHostToGuest "<vmx>" 本地 客户机
vmrun -T ws -gu root -gp <密码> runProgramInGuest "<vmx>" /bin/bash /tmp/x.sh
vmrun -T ws -gu root -gp <密码> copyFileFromGuestToHost "<vmx>" 客户机 本地
```

⚠️ 三个坑：
1. `runProgramInGuest` **不回传 stdout** → 脚本内重定向到文件再取回。
2. **从 Bash 调用** vmrun（PowerShell 调输出会被吞）。
3. 路径用 **Windows 原生格式** `'D:\...'`（Git Bash 的 `/d/` 会被转成 `d:\d\`）。
4. `runProgramInGuest` 的 `-c` 复杂命令会 exit 127，必须写成 `.sh` 脚本文件执行。
